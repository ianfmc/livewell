# Using gstack

- Use gstack to plan, review, and test clearly defined tasks.
- Follow this project's existing architecture and instructions.
- Use automated tests and validation checks to confirm changes pass.
- Deploy only when Ian explicitly requests it.
- Keep this project's context separate from other projects.
- Use sanitized sample data and authorized SAP development access.
- Never put credentials or sensitive data in skill configuration
  or checklist evidence.
- Keep gstack out of application dependencies and deployment packages.
- Record only sanitized verification results in the checklist.
